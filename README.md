1. LLM Wiki 主題與簡短介紹
主題： 半導體的微影魔法：黃光製程（Photolithography）基礎入門

簡短介紹： 本知識庫針對無半導體背景的初學者設計，透過「先討論架構、後分段生成」的方式，將繁雜的微影工程拆解為 5 個核心條目（微影概論、光阻化學特性、光罩與光學系統、Track 與 Scanner 聯機流程、曝光機演進與對準控制）。每個條目皆包含「生活化比喻」、「核心專有名詞解釋」與「常見迷思澄清」，作為後續生成教學簡報的唯一事實來源（Single Source of Truth）。

2. LLM Wiki 連結或成果
Wiki 知識庫架構與 Ingest 資料清單（共 5 篇）：

資料 1（#01 微影製程概論）： 整理晶圓製造中「洗照片」的類比概念與微影在前端製程（FEOL）的定位。

資料 2（#02 光阻化學特性與無塵室環境）： 收錄光阻劑對 UV 光的感光機制，以及無塵室採用 550~590nm 黃光照明的物理原因。

資料 3（#03 光罩與光學系統）： 整理光罩（Reticle）材質、縮小投影透鏡倍率（4:1）與成像原理。

資料 4（#04 Track 與 Scanner 聯機作業流程）： 彙整塗佈（Coating）、軟烤（Soft Bake）、曝光（Exposure）、曝光後烘烤（PEB）與顯影（Development）的標準循環。

資料 5（#05 曝光機演進與對準精準度控制）： 整理光源波長演進（i-line → KrF → ArF → EUV）與套準精度（Overlay）的重要性。

Wiki 檔案連結： https://github.com/barry526/LLM-Wiki/tree/975187b20bdef328fc32284804564f72b13a59e3/LLM%20Wiki

哪些步驟會重複執行？

步驟 2 ↔ 步驟 3（Wiki 知識建構迴圈）： 每 Ingest 一篇資料後，會重複執行「討論架構 → 生成條目 → 檢查白話程度」，直到 5 篇條目都達到初學者能理解的水準才進入下一階段。

步驟 5 ↔ 步驟 6（簡報生成與驗證迴圈）： 產出 HTML 後，需逐頁核對文字是否忠於 Wiki 並測試瀏覽器渲染效果，若發現錯誤便會退回修改再重新生成。

哪些地方需要檢查或重新生成？

檢查點 A（Wiki 條目層級）： 檢查專有名詞（如 Overlay、Reticle、Photoresist）是否都有搭配日常類比（例如「洗照片」），若太像硬梆梆的教科書就重新生成。

檢查點 B（簡報內容層級）： 檢查每一頁投影片是否引入了 Wiki 以外的外部知識，以及字數是否過多。

檢查點 C（前端互動層級）： 檢查生成的 HTML 在瀏覽器中是否能正常用按鈕與方向鍵切換，若腳本異常則重新生成 <script> 區塊。

為什麼這樣設計？

如果直接把 5 篇資料丟給 AI 一次生成簡報，模型很容易「自由發揮（產生幻覺）」或一次塞入太多專業細節。透過把流程拆成「Wiki 建構」與「簡報轉譯」兩個獨立迴圈，並強制在中間加入審查節點，能確保簡報內容100% 源自 Wiki，且維持穩定的教學節奏。

步驟四：實際執行反思
哪一個節點最常出錯？

「查詢 Wiki 並整理重點 → 產生簡報」這個節點最常出錯。因為 LLM 本身具備龐大的預訓練知識，當主題涉及半導體製程時，模型很容易「好心」補充 Wiki 裡沒有收錄的進階規格（例如在介紹 EUV 曝光機時自行加入 High-NA 數值孔徑等冷知識），導致簡報偏離原本設定的初學者教學難度。

你發現問題後，把檢查往前移到了哪一個步驟？

我把檢查點從「整份 HTML 簡報生成完畢後才人工肉眼核對」，往前移到了「步驟 4：規劃簡報大綱」階段（在還沒寫任何 HTML 標籤之前就先進行事實與難度審查）。

有沒有因此修改 Workflow / Graph？為什麼？

有。 我在流程中新增了一個「來源強制錨點（Citation Anchor）」的約束規則：要求 AI 在輸出每一頁簡報大綱前，必須先在該頁標註對應的 Wiki 條目編號（例如 📚 知識來源：LLM Wiki 條目 #04），若在 Wiki 中找不到對應段落就禁止寫入簡報。這樣做能從源頭阻斷模型自由發揮，大幅減少最後修改 HTML 程式碼的返工時間。
